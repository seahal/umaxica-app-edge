# Why there is no dependency-cruiser configuration here

`dependency-cruiser` was removed in the TypeScript 7 migration, not because the
invariants it held stopped mattering, but because it can no longer see the code.

v18.2.0 reaches for TypeScript's programmatic compiler API and declares
`typescript: >=2.0.0 <7.0.0`. TypeScript 7.0 does not publish that API — 7.1 is
the stated target — so run against this tree it reports:

```
‼ missing-typescript-transpiler: dependency-cruiser detected a TypeScript environment,
    but not a compatible TypeScript compiler (typescript: >=2.0.0 <7.0.0). This means
    it's likely to have missed TypeScript sources and dependencies.
    => Support for typescript@>=7 will follow when its API is published and stable.
```

and cruises **0 dependencies**. A gate that passes because it parsed nothing is
worse than no gate: it reads as coverage.

Where the invariants live now:

| Invariant                                 | Owner                                                           |
| ----------------------------------------- | --------------------------------------------------------------- |
| Import cycles                             | `import/no-cycle` + `import/no-self-import`, oxlint, every unit |
| Cross-deployment-unit imports             | `test/deployment-unit-boundaries.test.ts`                       |
| No `shared/` directory                    | `no-restricted-imports`, oxlint, every unit                     |
| Unused files / exports / dependencies     | Knip, per unit                                                  |
| Production code importing a devDependency | Knip, per unit                                                  |

Reinstate dependency-cruiser when it supports the TypeScript 7 API, and check
before doing so whether it still adds anything the four rows above do not.
